# 予報変動スコアの計算方法

[한국어](/docs/SCORING.md) | [English](/docs/SCORING.en.md) | **日本語**

## 概要

スコアは「n日前（1〜14）の予報が当日22時の予報（d0）とどれだけ一致したか」を0〜100で表します。100はd0と完全に同じで、低いほど予報が大きく揺れたことを意味します。実測値は使いません。コードは `accu_weather/daily.py` と `accu_weather/accuracy.py`、詳しい設計記録は [PLAN.md](PLAN.md) の5.1にあります。

1. 1時間ごとの予報24個を1日分の値1行にまとめます（n日前の予報ごとに、d0も同じ方法で）。
2. 1日分の値同士で「n日前 − d0」の差を求めます。天気・降水確率は同じ時間帯（3時間ごと）同士の差もあわせて見ます。
3. 5つの項目（気温、体感温度、降水確率、降水量、天気）をそれぞれ0〜1に変換します。0 = 同じ、1 = 基準値以上の差。
4. 5つの値にそれぞれ0.2を掛けて足したものが減点で、スコア = 100 × (1 − 減点) です。
5. d0を取得した時点（現地22時の収集直後）に、その日付の1〜14日前の14行を計算して `accuracy` テーブルに保存します。

## 1日分の値（日次集計）のルール

予報は1時間単位で取得し、1時間スロットのままでも保存しています。ただし、カレンダー、日別表示、グラフの1日単位表示のように1時間単位では表示しにくい場面や、スコアの計算では、日付ごとに値が1つ必要です。そのため、24個のスロットを1日1行にまとめた「1日分の値」を別に作ります。

1日分の値は「その日で最も悪い時点」に寄せてまとめます。降水量だけは合計です。

| 項目 | 24時間 → 1日 |
| --- | --- |
| 最高気温 / 最高体感温度 | 最大値 |
| 最低気温 / 最低体感温度 | 最小値 |
| 降水量 (mm) | 合計 |
| 降水確率 (%) | 最大値 |
| 天気 | 天気の重みが最も大きいコード（同じ場合はコード番号が大きい方） |
| 風 / 視程 | 最大値 / 最小値（スコアには使わない） |

## 項目ごとの差と0〜1への正規化

5つの項目は、人が受ける影響が重ならないように分けています。気温は暑さ・寒さ、体感温度は湿度・風・日差し、降水は濡れること、天気は移動・安全です。各項目は基準値で1に打ち切ります（`min(…, 1)`）。

| 項目 | 比較する値 | 0〜1のスコア | 1（最悪）になる基準 |
| --- | --- | --- | --- |
| 気温 | 最高・最低気温の差 | (\|最高の差\| + \|最低の差\|) / 2 ÷ 5 | 平均5℃以上の差 |
| 体感温度 | 最高・最低体感温度の差 | 気温と同じ式 | 平均5℃以上の差 |
| 降水確率 | 1日の最大確率の差 + 時間帯ごとの差 (%p) | (0.5 × \|最大の差\| + 0.5 × 時間帯ごとの差) ÷ 100 | 0% ↔ 100% |
| 降水量 | 1日の合計mm、平方根スケール | \|√予報 − √d0\| ÷ √10 | 0mm ↔ 10mm に相当する差 |
| 天気 | 代表天気コードの重み + 時間帯ごとの重み | 0.5 × \|重み(予報) − 重み(d0)\| + 0.5 × 時間帯ごとの差 | 晴れ(0) ↔ 強いひょうを伴う雷雨(1) |

- 降水量を平方根で見る理由：0 → 1mm（傘が必要になる）を10 → 11mm（どちらにせよ雨）より大きく捉えつつ（0.32 ↔ 0.15）、多い雨の側の差も小さくならないためです。√10 ≈ 3.16。

  | 変化 | 0 → 1 | 10 → 11 | 10 → 20 | 30 → 50 | 50 → 100 |
  | --- | --- | --- | --- | --- | --- |
  | 0〜1 | 0.32 | 0.15 | 0.41 | 0.50 | 0.92 |

  以前は対数スケール（\|log(1+予報) − log(1+d0)\| ÷ log(1+10)）を使っていましたが、比率だけを見るため 10 → 20mm が0.27、30 → 50mm が0.21と、0 → 1mm（0.29）よりも小さくなってしまうので変更しました。
- 体感温度を別項目にする理由：気温が同じでも、湿度や風の予報が変わると体感は変わるためです。Open-Meteo の `apparent_temperature` を使います。
- 差はDBに符号付きで保存します（+なら高めに予報）。スコアの計算でのみ絶対値を使います。
- 5つのうち1つでも値がなければ、スコアは空欄（None）になります。

## 天気・降水確率の時間帯ごとの比較

1日の代表値（その日で最も悪い天気、1日の最大降水確率）だけを比べると、代表値が同じ日は差が0になります。たとえばn日前の予報が「強い雨が2時間」、d0が「強い雨が20時間」でも、どちらも代表は強い雨なので天気の差は0です。雨が午前から夕方に移った場合も同じです。そこでこの2項目は1時間スロットもあわせて比べます。

1. 24時間を3時間ずつ8つのまとまり（00–02時、03–05時 …）に分けます。まとまりごとに、天気は重みが最も大きい値、降水確率は最大値を使います。
2. 同じまとまり同士で \|n日前 − d0\| を求め、8つの平均を取ります（時間帯ごとの差）。
3. 項目の値 = 0.5 × 1日の代表値の差 + 0.5 × 時間帯ごとの差。

| 状況（強い雨 0.45、曇り 0.05、雷雨 0.75） | 代表値の差 | 時間帯ごとの差 | 天気の値 |
| --- | --- | --- | --- |
| d0 0〜17時 強い雨 ↔ 予報 0〜2時 強い雨 | 0 | 5まとまり × 0.4 / 8 = 0.25 | 0.125 |
| d0 6〜11時 強い雨 ↔ 予報 15〜20時 強い雨 | 0 | 4まとまり × 0.4 / 8 = 0.2 | 0.1 |
| d0 14時に1時間の雷雨 ↔ 予報 終日曇り | 0.7 | 0.7 / 8 ≈ 0.09 | 0.39 |

- 半々にする理由：時間帯ごとの差だけだと、短い雷雨のような「その日に一度でも危険だったか」が8分の1に薄まります。代表値だけだと、上のように続く時間や時刻の変化が0になります。両方を混ぜて、どちらも捉えます。
- 3時間ずつにする理由：数日前の予報が雨の時刻を1時間単位で当てるのは難しいためです。同じまとまりの中で1〜2時間ずれたものは同じとみなし、午前 ↔ 夕方のような大きな変化だけを差として数えます。
- 1日の最大降水確率の差は符号付きで `precip_prob_diff` に、時間帯ごとの差は `precip_prob_hourly_diff`（%p）に保存します。天気は混ぜた値を `weather_diff` に保存します。
- 1時間スロットがない場合（両方にあるまとまりがない場合）は、代表値の差だけを使います。

## 天気の重み (weather_weight.json)

天気の重みは「その天気が移動・安全に与える影響」を0〜1で表した値です。雨の量や雨・雪の区別はすでに降水量・気温の項目で捉えているため、天気の項目ではそれらで捉えきれない霧による視界、雪道、路面凍結、突風、雷雨だけを見ます。

**決め方**（[`tools/weight_study.py`](tools/weight_study.py)）：さまざまな気候帯の24都市について28日分の1時間予報を取得し、各時間の4つのリスク要素を0〜1で評価して、天気コードごとに平均しました。

| 要素 | 0 | 1 |
| --- | --- | --- |
| 視界 | 視程5km以上 | 1km以下 |
| 雪 | 降雪0cm/h | 1時間あたり1cm以上 |
| 路面凍結 | 条件に当てはまらない | 1℃以下で降水があれば0.5 |
| 突風 | 30km/h | 70km/h以上 |

4つの要素は下の式でまとめます。1つが大きいだけでも値が大きくなり、重なるとさらに大きくなる「少なくとも1つが危険である確率」の形です。晴れの日にも吹く風の分（base）を引いて、晴れ = 0になるように合わせました。

```
影響 = 1 − (1 − 視界) × (1 − 雪) × (1 − 路面凍結) × (1 − 突風)
重み = (コードごとの影響の平均 − base) / (1 − base)      base = 晴れ（コード0）の影響の平均
```

**判断で調整したもの**：サンプルがほとんどないコード（着氷性の雨、強い雪、ひょうを伴う雷雨など）は自分で決めました。霧はデータ値0.99を0.8に下げました（視界は最悪でも、道路そのものが危険になるわけではないため）。雷雨は0.29を0.75に上げました（落雷・停電のリスクはデータに含まれないため）。強い雨は強度の順序に合わせて0.34を0.45に上げました。

| 種類 | コードと重み |
| --- | --- |
| 晴れ・曇り | 0 快晴 0、1 晴れ 0、2 一部曇り 0.05、3 曇り 0.05 |
| 霧 | 45 霧 0.8、48 着氷性の霧 0.9 |
| 霧雨 | 51 弱い 0.15、53 並 0.25、55 強い 0.35 |
| 着氷性の霧雨 | 56 弱い 0.5、57 強い 0.65 |
| 雨 | 61 弱い 0.35、63 並 0.4、65 強い 0.45 |
| 着氷性の雨 | 66 弱い 0.7、67 強い 0.9 |
| 雪 | 71 弱い 0.55、73 並 0.7、75 強い 0.85、77 霧雪 0.45 |
| にわか雨 | 80 弱い 0.4、81 並 0.6、82 激しい 0.7 |
| にわか雪 | 85 弱い 0.55、86 強い 0.85 |
| 雷雨 | 95 雷雨 0.75、96 弱いひょうを伴う 0.8、97 強い雷雨 0.9、99 強いひょうを伴う 1.0 |

データは10月下旬の1か月分なので、冬や梅雨の天気が少ないです。データが蓄積されたら、同じスクリプトで再計算する予定です。以前は（種類, 強度）座標の面積を使っていましたが、霧と弱い霧雨のように異なる天気の差が0になる問題があったため変更しました。

## 総合スコアと計算例

総合スコアは、5つの項目に同じ重み0.2をかけた減点を100から引いた値です。

```
スコア = 100 × (1 − 0.2 × (気温 + 体感温度 + 降水確率 + 降水量 + 天気))
```

例：ある日付の3日前の予報と当日（d0）の予報が次のとおりなら、スコアは56.9です。どちらも1日中同じ天気・降水確率だとすると、時間帯ごとの差は代表値の差と同じなので、天気・降水確率は代表値の差をそのまま使います。

| 項目 | 3日前の予報 | d0 | 計算 | 0〜1 |
| --- | --- | --- | --- | --- |
| 気温 | 最高20℃ / 最低10℃ | 18℃ / 11℃ | (2 + 1) / 2 ÷ 5 | 0.30 |
| 体感温度 | 19℃ / 8℃ | 16℃ / 9℃ | (3 + 1) / 2 ÷ 5 | 0.40 |
| 降水確率 | 60% | 20% | 40 ÷ 100 | 0.40 |
| 降水量 | 5mm | 0mm | √5 ÷ √10 = 2.24 ÷ 3.16 | 0.71 |
| 天気 | 63 雨 (0.4) | 3 曇り (0.05) | \|0.4 − 0.05\| | 0.35 |
| **合計** | | | 2.16 × 0.2 = 0.43 | スコア **56.9** |

月別・年別の画面は、このスコアを（都市, 期間, n日前）でまとめて平均・中央値を出したものです（[PLAN.md](PLAN.md) 5.2）。

## 設定値

項目の重み（0.2 × 5）、基準値（5℃、10mm）、時間帯ごとの比較のまとまりの大きさ（`block_hours = 3`）と代表値の割合（`peak_share = 0.5`）は `config.toml` の `[accuracy]` に、天気の重みは `weather_weight.json` にあります。いずれもデータが蓄積されたら調整する暫定値です。変更した後は `python3 -m accu_weather recompute` ですべて再計算します。
